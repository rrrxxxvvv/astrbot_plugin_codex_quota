# Codex 额度推送 v1.3.1

独立 AstrBot 插件。桌面上传必须绑定 QQ，插件按 QQ 分别保存额度，自动推送和查询都使用这一绑定，不向所有好友广播。


## 配套项目与依赖

- 桌面采集端：[codex-quota-monitor](https://github.com/rrrxxxvvv/codex-quota-monitor)。必须在已登录 Codex 的 Windows 电脑运行；本插件不直接访问 OpenAI 账号，不自行采集额度。
- 本插件安装在 AstrBot 服务器，可独立于疙瘩插件使用。
- Python 3.10+；已在 Python 3.12、AstrBot 4.24.2 上部署验证。需要支持插件 initialize/terminate 生命周期与配置接口的 AstrBot 版本。
- aiohttp 3.9–3.x，依赖见 requirements.txt；AstrBot 通常已包含此库。
- OneBot v11 / NapCat QQ 平台，支持 get_friend_list 和私聊发送；暂不支持 QQ 官方机器人适配器。
- 桌面到服务器接收端口需网络可达，默认 TCP 18765。

## 安装示例

将仓库克隆到 AstrBot 数据目录的 plugins 下：

```bash
cd /path/to/AstrBot/data/plugins
git clone https://github.com/rrrxxxvvv/astrbot_plugin_codex_quota.git
# 在 AstrBot 使用的 Python 环境安装依赖（若宿主未自动安装）：
python -m pip install -r astrbot_plugin_codex_quota/requirements.txt
```

在 AstrBot 管理面板加载/重载插件后配置。若使用 Docker，接收端口要映射到 AstrBot 服务，例如在其 compose 服务中添加：

```yaml
ports:
  - "18765:18765"
```

修改端口映射后需重新创建 AstrBot 容器，仅重载插件不会添加 Docker 端口。保留已有面板与 OneBot 端口设置。若启用 HTTPS 反向代理，转发 /v1/quota 至接收端口。

## 配置步骤

1. 更新服务器插件并重载，重新打开配置页复制自动生成的连接密钥。密钥重启不变，已有密钥沿用；清空保存并重载才会重新生成。
2. 插件启用额度接收。监听 IP 通常保持 0.0.0.0，端口默认 18765；服务器放行端口，Docker 需映射端口。
3. 桌面打开“AstrBot 推送”，填写服务器 IP:端口或 HTTPS 根地址、绑定 QQ 号、同一密钥，然后启用上传。
4. 用绑定 QQ 添加机器人为好友。首次上传建立基线，后续额度重置或增加时通知。

公网 IP 填在桌面端；监听 IP 是服务器网卡绑定地址。连接密钥不是 OpenAI API 密钥。QQ 平台自动识别，无需填写平台 ID。同一 QQ 是多个机器人平台的好友时，可能分别收到通知。

## 查询与推送开关

- /额度查询（别名 /周额度、/codex额度）：只查发送者 QQ 对应的额度。
- /开启额度推送：开启自己的通知，默认开启。
- /关闭额度推送：关闭自己的通知，仍可查询。
- /额度推送状态：查看自己的开关。

仅好友私聊可用；未绑定的 QQ 会收到未绑定提示，不返回其他人的额度。开关按平台私聊会话保存，重启保留。

显示实际返回的额度窗口、已用及剩余比例、重置时间和最后采集时间，均为北京时间。超过 3 分钟未采集会提示数据过期。显示官方只读接口返回的重置卡剩余次数，以及每张可用重置卡的到期时间（北京时间）。接口未提供时明确显示未知，不会使用或核销重置卡。

## 上传与数据

上传间隔可设为 15–86400 秒，默认 60 秒；失败按此间隔重试。额度仍每分钟采集，间隔较长会延迟通知。

数据保存在 AstrBot 数据目录下 plugin_data/astrbot_plugin_codex_quota/accounts/<QQ>.json，包含 QQ、快照和待发通知；push_preferences.json 保存推送开关。

支持多个 QQ，各自数据隔离。一个 QQ 当前对应一份最新额度，不应让多个不同账号同时向同一 QQ 上传。修改桌面绑定 QQ 后，新 QQ 建立自己的记录，原 QQ 历史保留并逐渐标记过期。持有连接密钥的桌面端可以指定 QQ，仅向可信上传端提供密钥。

## 升级

桌面和插件必须一起更新。本版使用带 QQ 的 v2 数据格式，路径仍为 /v1/quota。旧上传不带 QQ 会被拒绝，新上传也会被旧插件拒绝，避免误广播。

旧 codex_quota.json 没有 QQ，保留但不用于推送或查询。填写桌面 QQ 后重新上传。旧接收 QQ 白名单不再使用，绑定来自通过签名验证的上传内容。

## 安装及边界

把整个插件目录放入服务器 AstrBot data/plugins/，安装 requirements.txt 依赖后重载。支持 OneBot/NapCat 私聊，不依赖疙瘩插件，不调用模型。

只上传 QQ、账号标识哈希、额度及时间，不传登录凭证或聊天历史。HTTP 签名不加密内容，需要保密时使用 HTTPS。

电脑离线时不采集，恢复上传最新快照；期间短暂额度变化可能无法捕捉。发送失败会重试，发送成功后立即崩溃可能导致少量重复通知。

已通过本地 HTTP 与模拟 QQ 联调，尚未验证远程服务器真实 QQ 送达。

## 重置卡到期提醒

每张可用重置卡剩余严格不足 7 天、严格不足 24 小时时，各向绑定 QQ 提醒一次；记录保存在对应 QQ 数据文件中，重启不重复。首次看到已不足一天的卡会合并两档提醒为一条消息。沿用 /开启额度推送 和 /关闭额度推送。

每 30 秒检查一次，需桌面上传最近 3 分钟内的有效数据；数据过期时暂缓提醒，恢复采集后补充判断，以免已使用的卡被误报。已用、已移除、已到期的卡不再发送待发提醒。上传间隔过长或电脑离线会延迟提醒。卡标识只上传不可逆哈希用于区分与去重，不上传原始卡 ID。

## 开发检查

执行 `python tests/test_card_expiry.py` 可检查两档提醒边界、按卡去重、重启持久化及过期数据处理，不会发送真实消息。

## 额度更新分类

推送标题区分“每周额度更新”“五小时额度更新”“OpenAI 重置（推测）”和“可用额度增加”。原定周期结束且接口返回新周期时属于正常周期更新；原周期尚未结束且用量提前归零时标为推测的 OpenAI 重置。接口不提供原因，无法确认是官方操作还是用户使用重置卡。仅部分用量下降只提示可用额度增加。多种变化同时发生时合并标题并逐项说明。

分类测试：`python tests/test_update_categories.py`。
